ShadowMap
Predicting Urban Heat Before It Happens

A geospatial ML pipeline that predicts block-level urban heat across Delhi — now a university grant-funded research project, from satellite data to an interactive map.

Role Geospatial ML Engineer — grant-funded, PI-supervised
Status Active research project
Links → Live | → GitHub
01
The problem

Heat doesn't fall evenly across a city. Some blocks run several degrees hotter than others because of building density, vegetation cover, and surface material — but most public heat data comes from satellites at a resolution too coarse to act on. If you're a city planner deciding where to add tree cover or reflective roofing, "this district is hot" isn't specific enough to do anything with.

02
Approach

I fused three different data sources: Sentinel-3 land surface temperature for the thermal signal, Landsat NDVI for vegetation cover, and OpenStreetMap for building density and street network structure. Those don't share a native resolution or format — satellite rasters, vector geometry — so a meaningful chunk of the work was building features that meant the same thing at the block level regardless of which dataset they came from.

On top of that, I trained an XGBoost model using quantile regression instead of a single point estimate, because a planner deciding where to intervene needs to know the range of likely outcomes, not just the median one.

03
Making it usable

A model that only exists as a notebook doesn't help anyone. I built a FastAPI backend to serve predictions and a React + Leaflet.js frontend so the output is an interactive map, not a spreadsheet — you can click a block and see its predicted heat range, not just a number in isolation. That was the harder half of the project: the modeling was a solved-shaped problem, but making climate data interpretable to someone without a data science background took as much thought as the model itself.
